# VUE WAXING 리디자인 보고서

## 1. 기존 코드 감사
첨부 ZIP의 src/template.html, src/main.css, src/main.js, README 및 배포 HTML을 직접 확인했다.
- 실제 JS 기능: 모바일 메뉴, 읽기 진행률, IntersectionObserver 등장, 정밀 포인터 패럴랙스, 3개 탭의 이미지·문구 변경, 가로 갤러리 드래그·버튼, 상담 문구 생성·복사. 기능이 전혀 없는 사이트라는 평가는 정확하지 않다.
- 스크롤은 진행률과 등장만 제어한다. 이야기 내용의 순서를 변경하지 않는다.
- CSS의 aria-current 선택자는 있지만 JS에서 활성 상태를 갱신하지 않는다.
- 갤러리 tabindex는 있으나 명시적인 방향키·Home·End 처리와 현재 이미지 설명 갱신은 없다.
- Hero는 어두운 배경, 사진 그라데이션, 최대 119px 제목에 의존한다. 한글 자간 -.095em은 글자 밀도를 지나치게 높인다.
- 100~240px 여백과 유사한 대형 제목이 연속되며 장면의 중요도가 평준화된다.
- 선언한 Pretendard/Noto 폰트 파일은 제공되지 않아 기기별 렌더링이 달라진다.
- 모바일 미디어 쿼리는 있으나 Hero 반응은 fine pointer에만 제한된다. 모바일 UX 완성 여부는 코드만으로 확정할 수 없다.
- 루트/public HTML 두 벌과 치환 토큰이 있는 src 템플릿은 수정과 배포 기준을 분산한다.
- 재사용: 접근성 기본 마크업, 실제 상담 생성·복사, 탭 키보드, 원본에 포함된 연출 이미지. 교체: 어두운 Hero 구성, 컬러·타입·여백 체계, 반복 등장 중심의 스크롤, 중복 배포 파일.

## 2. 아트 디렉션 비교
| 방향 | 특징 | 판단 |
|---|---|---|
| 피부결 아카이브 | 종이색, 올리브, 곡선, 순번과 관찰 기록 | 선택. 개인차를 이해하는 순서를 보여주기 좋음 |
| 화이트 트리트먼트 스튜디오 | 백색, 직선, 간결한 정보 | 위생적이나 의료 공간처럼 읽힐 위험 |
| 로즈 프라이빗 살롱 | 로즈, 부드러운 사진, 친밀한 문장 | 기존 베이지 뷰티 사이트와 차이가 작음 |

## 3. 설계
Hero → 철학 → 순서형 이야기 → 선택형 경험 → 무드 갤러리 → 방문 안내 → 상담 메모.
배경 #f6f5ee, 잉크 #303d34, 보조 #718062. 한글은 OS 기본 고딕을 사용하며 외부 폰트 요청은 없다. 데스크톱 Hero는 텍스트/아치 이미지의 비대칭 구성, 모바일은 텍스트 후 우측으로 치우친 세로 이미지다. 사진은 원본의 AI 연출 이미지이며 실제 매장으로 표시하지 않는다.

## 4. 모션 명세
| 기능 | 트리거 / 상태 | 시간 / easing | 모바일 |
|---|---|---|---|
| Hero | 진입 시 텍스트·이미지, 곡선 선 그리기 | 1.13~2.8초 / cubic-bezier | 동일 등장, 터치 시 곡선 이동 |
| 포인터 | 중심에서 ±약 14px 곡선 이동 | .7초 ease-out | pointerdown |
| 이야기 | 각 장 중앙 진입 → 상단 현재 단계·강조 갱신 | 즉시 | 세로 흐름 유지 |
| 선택 | 탭 선택 → 이미지·본문·상담 주제 갱신 | 기존 프레임 전환 | 탭 터치 |
| 갤러리 | 드래그/버튼/키보드 → 가로 이동·설명 변경 | 브라우저 smooth | native swipe |
| 상담 | 선택·입력 → 문구 갱신 | 즉시 | 동일 |
Reduced motion에서는 CSS 애니메이션과 전환, smooth scroll을 끄고 포인터 효과를 생략한다.

## 5. 첫 구현 후 재검토와 수정
첫 구현에서 밝은 배경으로 바꾼 후 기존 어두운 탭 글자색이 남는 문제가 있어 .ritual-step, 설명 및 번호 색상을 올리브 계열로 재지정했다. 모바일 Hero를 데스크톱 축소 대신 세로 flex 구성으로 수정하고 제목을 42px로 제한했다. 갤러리 두 번째 이미지에 상단 여백을 주어 균일한 카드 리듬을 조정했다. 숨겨진 reveal 기본값을 해제하여 콘텐츠가 스크립트 상태에 의존하지 않게 했다. 이는 코드 검토 기반 수정이며 브라우저 관찰 결과로 주장하지 않는다.

## 6. 검증 결과와 한계
- PASS: node --check assets/main.js, assets/config.js.
- PASS: HTML의 로컬 src/href 자산 존재 확인, 배포 HTML 1개 확인.
- 미검증: 실제 데스크톱/모바일 렌더링, 터치 스와이프, 클립보드 권한, 키보드 포커스 이동, 실제 스크롤 타이밍, 스크린리더, Cloudflare 원격 배포.
- 따라서 본 패키지는 구현본이며 사용자 요청의 브라우저 검증 합격을 확정한 최종 승인본은 아니다. 실제 운영 사진, 주소, 연락처, 예약 URL도 필요하다.

## 7. 수동 검증 체크리스트
1440×900, 390×844, 320×568에서 가로 넘침 확인. 탭 방향키, 갤러리 좌우/Home/End, 모바일 메뉴 Escape, 상담 주제 동기화, 질문 입력과 복사 결과를 확인한다. JavaScript 비활성 및 reduced-motion에서 내용 노출을 확인한다. 콘솔 오류와 네트워크 404를 확인한다.
